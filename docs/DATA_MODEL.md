# Data Model

Prisma schema as designed. The implemented schema is `prisma/schema.prisma` (Prisma **7.10**). Where it differs from this draft, see "Implementation notes (M1)" below.

Conventions:
- IDs are `cuid()` strings. Telegram IDs are `BigInt` (they can exceed 2³¹).
- Money is `Int` rupiah (max ≈ Rp2,1 miliar per row, which is plenty). Sums are aggregated in code or DB as bigint/number.
- `localDate` is the WIB calendar date (`@db.Date`). `occurredAt` is the exact instant (`@db.Timestamptz`).
- Every user-owned table has `userId` with an index.

## Implementation notes (M1)

Checked against the Prisma 7 docs on 2026-10-31. Differences from the draft below:

| Topic | Draft | Implemented | Why |
|---|---|---|---|
| Generator | `prisma-client-js` + `previewFeatures = ["driverAdapters"]` | `provider = "prisma-client"`, `output = "../server/db/generated"`, `moduleFormat = "esm"`, `importFileExtension = "js"`. No preview features | Prisma 7: `output` is required, `prisma-client-js` is deprecated, driver adapters are GA. The generated client is TypeScript compiled with the rest of `server/`. It has `.js` imports so it runs as Node ESM on Vercel (D-022). It's gitignored and regenerated by `postinstall` and the build |
| Datasource | `url` + `directUrl` in the schema | Only `provider = "postgresql"` in the schema | Prisma 7 deprecates connection URLs in the schema |
| CLI connection | `directUrl` | `prisma.config.ts` → `datasource.url = DIRECT_URL` (non-pooled) | Prisma 7 reads the CLI connection from `prisma.config.ts`. It doesn't load `.env` (Prisma 7 default, kept on purpose: only the Vercel build should reach the production DB) |
| Runtime connection | `url` (pooled) | `server/db/prisma.ts`: `new PrismaClient({ adapter: new PrismaNeon({ connectionString: DATABASE_URL }) })`, created lazily, one per function instance | Prisma 7 requires a driver adapter. `PrismaNeon` uses WebSockets (interactive transactions work) via Node's built-in `WebSocket` (Node ≥ 22), so there's no `ws` package |
| `MagicLinkToken` | no index on `userId` | `@@index([userId])` | "Every user-owned table has `userId` with an index" (also used for the 5/hour limit) |
| `amount > 0` CHECK | `Transaction` | `Transaction` **and** `PurchaseIntent` | Same rule for intents (the amount comes from `parseAmount`) |
| Raw SQL | — | Migration `20261031000100_constraints`: `Transaction_amount_positive`, `PurchaseIntent_amount_positive`, `User_pct_sum_100`, `category_system_slug` | These aren't expressible in the Prisma schema, so `migrate diff` between schema files never sees or drops them |
| Seed IDs | — | System categories have fixed ids `sys_<slug>` (`sys_belanja_bulanan` etc.) and `emoji` NULL | Stable ids for data migrations; no emoji was specified |

Unchanged from the draft and worth knowing: `PurchaseIntent.categoryId` and `ChatState.userId` have **no foreign key** (no relation is declared). Required relations use Prisma's default `ON DELETE RESTRICT`, so account deletion (P1) must delete child rows first.

Repositories (`server/db/repos/*Repo.ts`) are factories, `createTxRepo(db)` etc., taking the client or a transaction client. Every function on user data takes `userId` first and puts it in `where` (`tests/db/repoScoping.test.ts` checks this for tx, intent, category, alias, and chat-state repos). A few functions are deliberately not user-scoped: token/invite lookups by hash (they're how the user is found), housekeeping deletes, and `categoryRepo.listSystem`.

Implementation notes (M5, the bot's logging loop, BOT_SPEC §3.5):
- **`ChatState.payload`** always has a `nonce` that is also in the question's button data. `chatStateRepo.take(userId, kind, nonce, now)` claims the state with a conditional delete (`payload.nonce` matched by a JSON path filter), so of two taps only one gets it. Payloads: `AWAIT_AMOUNT` / `CONFIRM_AMOUNT` `{ nonce, base, rawText, occurredAt, candidate? }`; `AWAIT_CATEGORY` `{ nonce, amount, item, rawText, occurredAt }`. They're validated with Zod when read back.
- **`RateLimit`** also holds `income-nudge:<userId>:<YYYY-MM>` (expires at the end of that WIB month): its first hit is "the first message of a month without income" (PRD F12).
- **`txRepo.findById` and `latest`** include the category (bot replies show its name).

## Draft schema

```prisma
generator client {
  provider = "prisma-client-js"     // ⚠ superseded, see Implementation notes
  previewFeatures = ["driverAdapters"] // ⚠ superseded
}

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")   // pooled; ⚠ superseded (runtime: driver adapter)
  directUrl = env("DIRECT_URL")     // migrations; ⚠ superseded (prisma.config.ts)
}

enum Role          { OWNER MEMBER }
enum UserStatus    { ACTIVE DISABLED }
enum Bucket        { NEEDS WANTS SAVINGS INCOME }
enum TxType        { INCOME EXPENSE SAVING }
enum TxSource      { BOT WEB }
enum ParseMethod   { RULE ALIAS LLM USER_PICK MANUAL }
enum Verdict       { ALLOW CAUTION DENY NO_BUDGET }
enum IntentStatus  { PENDING BOUGHT SKIPPED EXPIRED }

model User {
  id               String     @id @default(cuid())
  telegramId       BigInt     @unique
  telegramUsername String?
  firstName        String?
  role             Role       @default(MEMBER)
  status           UserStatus @default(ACTIVE)
  botBlocked       Boolean    @default(false)
  needsPct         Int        @default(50)
  wantsPct         Int        @default(30)
  savingsPct       Int        @default(20)
  timezone         String     @default("Asia/Jakarta")
  createdAt        DateTime   @default(now())
  updatedAt        DateTime   @updatedAt

  transactions   Transaction[]
  categories     Category[]
  aliases        KeywordAlias[]
  intents        PurchaseIntent[]
  noSpendDays    NoSpendDay[]
  sessions       Session[]
  magicTokens    MagicLinkToken[]
  invitesCreated Invite[] @relation("InviteCreator")
  invitesUsed    Invite[] @relation("InviteUser")
}

model Invite {
  id          String    @id @default(cuid())
  codeHash    String    @unique          // sha256(code); the plain code is never stored
  createdById String
  createdBy   User      @relation("InviteCreator", fields: [createdById], references: [id])
  expiresAt   DateTime
  usedAt      DateTime?
  usedById    String?
  usedBy      User?     @relation("InviteUser", fields: [usedById], references: [id])
  createdAt   DateTime  @default(now())
}

/// System categories have userId = null and are seeded. Users may add their own.
model Category {
  id        String   @id @default(cuid())
  userId    String?
  user      User?    @relation(fields: [userId], references: [id])
  slug      String                       // "makan", "jajan", ...
  name      String                       // "Makan"
  emoji     String?
  bucket    Bucket
  keywords  String[]                     // default keywords (system categories)
  archived  Boolean  @default(false)
  createdAt DateTime @default(now())

  transactions Transaction[]
  aliases      KeywordAlias[]

  @@unique([userId, slug])
  @@index([userId])
}

/// Learned per-user mapping, e.g. "cireng" → jajan, created when the user corrects a category.
model KeywordAlias {
  id         String   @id @default(cuid())
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  keyword    String                       // normalized lowercase
  categoryId String
  category   Category @relation(fields: [categoryId], references: [id])
  createdAt  DateTime @default(now())

  @@unique([userId, keyword])
}

model Transaction {
  id          String      @id @default(cuid())
  userId      String
  user        User        @relation(fields: [userId], references: [id])
  type        TxType
  amount      Int                          // rupiah, > 0
  categoryId  String?                      // required for EXPENSE and SAVING
  category    Category?   @relation(fields: [categoryId], references: [id])
  note        String?                      // e.g. "cireng"
  rawText     String?                      // original chat message (bot only)
  occurredAt  DateTime    @db.Timestamptz
  localDate   DateTime    @db.Date         // WIB date; drives all budget math
  source      TxSource
  parseMethod ParseMethod
  createdAt   DateTime    @default(now())
  updatedAt   DateTime    @updatedAt
  deletedAt   DateTime?

  intent      PurchaseIntent?

  @@index([userId, localDate])
  @@index([userId, type, localDate])
}

model PurchaseIntent {
  id            String       @id @default(cuid())
  userId        String
  user          User         @relation(fields: [userId], references: [id])
  item          String
  amount        Int
  categoryId    String
  verdict       Verdict
  status        IntentStatus @default(PENDING)
  localDate     DateTime     @db.Date
  expiresAt     DateTime
  decidedAt     DateTime?
  transactionId String?      @unique
  transaction   Transaction? @relation(fields: [transactionId], references: [id])
  createdAt     DateTime     @default(now())

  @@index([userId, status, localDate])
}

/// "Hari ini emang ga keluar duit" — suppresses the daily reminder.
model NoSpendDay {
  userId    String
  user      User     @relation(fields: [userId], references: [id])
  localDate DateTime @db.Date
  createdAt DateTime @default(now())

  @@id([userId, localDate])
}

model Session {
  id         String   @id @default(cuid())
  tokenHash  String   @unique               // sha256(random 32 bytes)
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  expiresAt  DateTime
  lastSeenAt DateTime @default(now())
  userAgent  String?
  revokedAt  DateTime?
  createdAt  DateTime @default(now())

  @@index([userId])
}

model MagicLinkToken {
  id        String    @id @default(cuid())
  tokenHash String    @unique
  userId    String
  user      User      @relation(fields: [userId], references: [id])
  expiresAt DateTime                        // now + 5 min
  usedAt    DateTime?
  createdAt DateTime  @default(now())
}

/// Short-lived conversation state, e.g. waiting for an amount ("Berapa duitnya?")
/// or confirming an ambiguous one ("Maksudnya Rp20.000?"). One row per user; overwritten.
model ChatState {
  userId    String   @id
  kind      String                        // "AWAIT_AMOUNT" | "CONFIRM_AMOUNT" | "AWAIT_CATEGORY"
  payload   Json                          // e.g. { item, type, candidateAmount }
  expiresAt DateTime                      // now + 10 min
  updatedAt DateTime @updatedAt
}

/// Telegram retry protection.
model ProcessedUpdate {
  updateId  BigInt   @id
  createdAt DateTime @default(now())
}

model CronRun {
  runKey    String   @id                    // "daily-reminder:2026-10-30"
  createdAt DateTime @default(now())
  finishedAt DateTime?
  stats     Json?
}

model RateLimit {
  key         String   @id                  // "msg:<userId>:<yyyymmddhhmm>" or "llm:<userId>:<yyyymmdd>"
  count       Int      @default(0)
  expiresAt   DateTime

  @@index([expiresAt])
}
```

## Invariants (enforce in code + tests)

| Rule | Where |
|---|---|
| `amount > 0` | Zod schema + DB `CHECK (amount > 0)` via a raw SQL migration |
| `EXPENSE` → category bucket ∈ {NEEDS, WANTS}; `SAVING` → bucket = SAVINGS; `INCOME` → category null or bucket INCOME | service layer |
| `localDate` = WIB date of `occurredAt` | set in exactly one function: `toLocalDate()` |
| A user can only reference their own or system categories | service layer check on create/update |
| `needsPct + wantsPct + savingsPct = 100` | Zod + DB CHECK |
| System category slugs are unique | Postgres treats NULLs as distinct, so `@@unique([userId, slug])` does **not** protect system rows (`userId = null`). Add a raw SQL partial index: `CREATE UNIQUE INDEX category_system_slug ON "Category"(slug) WHERE "userId" IS NULL;` |

## Housekeeping (inside the daily cron)

- Delete `ProcessedUpdate` older than 7 days, expired `RateLimit` rows, and `MagicLinkToken` older than 1 day.
- Mark `PurchaseIntent` with status `PENDING` and `expiresAt < now()` as `EXPIRED`.
- Delete sessions that have been expired or revoked for > 30 days.

## Seed: default categories

There's no local environment, so the seed is a **SQL data migration** (`<ts>_seed_categories/migration.sql`) applied by `prisma migrate deploy`. Use `INSERT … ON CONFLICT (slug) WHERE "userId" IS NULL DO NOTHING` (relies on the partial unique index above). To add or change keywords later, write a new data migration. Don't edit an applied one.

| slug | name | bucket | sample keywords |
|---|---|---|---|
| makan | Makan | NEEDS | warteg, nasi, padang, makan siang, makan malam, sarapan, gofood, grabfood, shopeefood |
| transport | Transport | NEEDS | gojek, goride, gocar, grab, maxim, ojol, krl, transjakarta, tj, mrt, lrt, bensin, parkir, tol, angkot |
| belanja-bulanan | Belanja Bulanan | NEEDS | belanja bulanan, sabun, sampo, deterjen, odol, superindo |
| kuota | Kuota | NEEDS | kuota, pulsa, paket data, internet |
| jajan | Jajan | WANTS | jajan, cireng, donat, boba, seblak, cilok, martabak, cemilan, snack, es kopi, kopi |
| nongkrong | Nongkrong | WANTS | nongkrong, cafe, kafe, ngopi bareng, nonton, bioskop, karaoke |
| nabung | Nabung | SAVINGS | nabung, tabungan, reksadana, saham, emas, deposito |
| uang-jajan | Uang Jajan | INCOME | uang jajan, uang saku, dikasih, transfer mama, transfer papa, gaji |

Minimarkets (indomaret, alfamart) are ambiguous (snacks vs. groceries). Don't map them by default; let the LLM decide or ask the user. "gofood/grabfood" → **makan**, not transport.
